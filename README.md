# Atlas (Rust)

Воссоздание CRM «Атлас» по каталогу `D:\Atlas-catalog` (ТЗ). Стек: axum 0.8, sqlx 0.9 (PostgreSQL), argon2, JWT.

## Состояние
Сделано (шаг 1 по порядку из `rust-implementation.md`):
- `crates/domain` — модули организации (17), 51 право, роли «Админ»/«Продавец»; юнит-тесты.
- `crates/api` — миграция `0001_core.sql`; вход/регистрация, организации (модули), филиалы, роли, сотрудники, справочник прав; единый формат ошибок `{statusCode, message, error}`.
- `tests/core_flow.rs` — сквозной тест на реальном PostgreSQL.

Шаг 2 — каталог: `0002_catalog.sql`, `/api/product-categories`, `/api/suppliers`, `/api/product-units` (5 единиц по умолчанию при регистрации), `/api/products` (цены и доступность по филиалам, штрихкоды, составные товары с расчётом себестоимости и защитой от циклов, копия, поиск/фильтры); `domain::catalog`; тест `catalog_flow`.

Шаг 3 — продажа: `0003_sales.sql`; `/api/lists/{kind}` (методы оплаты/покупки, скидки, причины, категории расходов — значения по умолчанию при регистрации), `/api/clients`, `/api/saved-carts`, `/api/sales` (скидка, надбавка, бонусы и кэшбэк, смешанная оплата, кастомные позиции, идемпотентность, списание остатков с учётом составных «во время продажи», возвраты, удаление со сторно), `/api/stocks` (остатки, история движений, ручная установка); `domain::sale`; тест `sale_flow`.

Шаг 4 — склад: `0004_stock_documents.sql`; `/api/supplies` (приёмка, возврат поставщику, обновление закупочных цен, привязка к заказу), `/api/supply-orders` (+ `/suggest` — предложение к заказу, дизайн), `/api/writeoffs`, `/api/revisions` (остаток приводится к факту, разница по себестоимости), удаление документов сторнирует движения; `/api/stocks` — «продажи/списания за 7 дней» и `/summary` (остаток по закупочной/продажной цене); тест `stock_flow`.

Шаг 5 — финансы и отчёты: `0005_finance.sql`; `/api/wallets` (денежные счета, баланс = сумма проводок, пополнение/изъятие, переводы), `/api/spendings` (операционные и капитальные, списывают со счёта, удаление сторнирует), `/api/recurring-expenses` (доля по дням месяца), оплата приёмки со счёта; комиссия методов оплаты; `/api/reports/{sales,profit,products,revisions,home}` с `format=csv`; `domain::finance` (P&L, доля ежемесячных расходов).

Шаг 6 — лояльность и заказы: `0006_complex_orders_loyalty.sql`; проверка включённых модулей (права выключенного модуля не действуют даже у админа); `/api/loyalty-settings`, `/api/sale-settings`, `/api/marketplace-settings`; кэшбэк с уровнем из настроек, карта «N-й товар в подарок», постоянная скидка клиента, ручные бонусы (идемпотентно), стоимость доставки; клиенты (маска телефона, статистика, история); `/api/complex-sales` (+ шаблоны, оплаты на денежные счета, списание материалов, статусы, учёт в P&L); `/api/orders` и публичный онлайн-каталог `/api/marketplace/*`, `POST /api/orders/public`, создание продажи из заказа; тест `complex_flow`.

Шаг 7 — импорт и массовое редактирование: `0007_import.sql`; `POST /api/import/products` и `/api/import/sales` (CSV/TSV строкой в `content`, автоопределение разделителя, пробный прогон `dryRun`, ошибки «Строка N: …», продажи по клиенту и дате объединяются, партия импорта откатывается `DELETE /api/import/batches/{id}`); `GET /api/export/{products,clients}` (CSV/JSON); `PATCH /api/products/batch` (всё или ничего); `domain::csv`; тест `import_flow`. Файлы .xlsx не читаются — только CSV/TSV.

Шаг 8а — смены, зарплата, чеклист: `0008_shifts_salary_checklist.sql`; `/api/shifts` (открытие, закрытие с расчётом наличных и недосдачей, отмена закрытия, внесение/изъятие, сотрудники смены, **автозакрытие** фоновой задачей по времени и поясу филиала; продажа без открытой смены запрещена при включённом модуле, кроме права `sale.without_shift`); счёт «Наличные с кассы» (`isCashRegister`); `/api/salary` (за час / за день / за месяц + % от личных продаж, выплаты со счёта, баланс за период и за всё время), `/api/working-hours`; `/api/checklist` (пункты, отметки с временем и сотрудником, сброс по дням); в P&L — зарплаты и разница закрытия смен; `domain::salary`; тест `shift_flow`.

Шаг 8б — склад и операции: `0009_transfers_manufacture_payments.sql`; `/api/transfers` (проверка остатка, сторно при удалении), `/api/manufactures` (+ `/preview`, фактический расход ингредиентов, себестоимость партии) и `POST /api/import/manufactures`; `/api/payments` (денежные транзакции за период, фильтр по дате создания или периоду, `/report` — движение денег по счетам); лента `/api/updates` (изменения цен, удаления документов, непрочитанные); `/api/label-settings`, `/api/labels/render` (данные для печати этикеток); закрытие смены по способам оплаты (QR/терминал, блоки «по способу» и «по сотрудникам»); пункты чек-листа: ежедневные, разовые, разделы; тест `ops_flow`.

Шаг 9 — API-токены и агент: `0010_api_tokens.sql`; `/api/api-tokens` (секрет `atl_…` показывается один раз, хранится SHA-256, права `read`, `read:products`, `read:stock`, `read:sales`, `draft:sales`, `draft:acceptances`, срок 30/90/365 дней, отзыв, журнал действий); `/api/v1/*` (whoami, филиалы, товары, продажи, приёмки, отчёты, остатки) по токену; черновики продаж и приёмок от агента (`/api/v1/*/drafts`) и их проведение/отклонение пользователем (`/api/api-drafts`); права `write:*` помечены «скоро»; тест `api_flow`.

**Бэкенд по плану `rust-implementation.md` (шаги 1–9) реализован.** Не сделано: интерфейс, Excel (.xlsx), чат поддержки, печать накладных и шаблоны печати, ценовые категории, модификаторы товаров, фискализация (ОФД), реальная отправка рассылок, отдельные сессии с refresh-токеном и офлайн-очередь продаж.

Не сделано в шаге 5: экспорт в Excel (только CSV); зачисление выручки на денежные счета по методам оплаты; категории расходов «только для админов»; зарплаты и разница закрытия смен в P&L равны 0 до модулей «Смены» и «Зарплата». Отчёты считают период в UTC.

## Запуск
```bash
export DATABASE_URL=postgres://postgres:secret@127.0.0.1:54329/atlas
export JWT_SECRET=change-me
export ALLOW_SIGNUP=false     # закрытая установка: регистрация новых компаний выключена (по умолчанию включена)
cargo run -p atlas-api        # слушает BIND (по умолчанию 0.0.0.0:8080; на Windows порт 8080 может быть закрыт — BIND=127.0.0.1:8787), миграции применяются при старте
```

## Тесты
```bash
cargo test -p atlas-domain
TEST_DATABASE_URL=postgres://postgres:secret@127.0.0.1:54329/atlas_test cargo test -p atlas-api
```
Без `TEST_DATABASE_URL` тест пытается скачать встроенный PostgreSQL с GitHub API (может упереться в rate-limit).

Тесты с `TEST_DATABASE_URL` пересоздают схему `public` — используйте отдельную тестовую БД.
